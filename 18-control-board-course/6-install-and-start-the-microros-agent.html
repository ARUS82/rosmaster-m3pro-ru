Примечание: можно выбрать любой из трёх способов запуска.

1. Запуск агента micro-ROS через Docker

Запуск serial-прокси через Docker

docker run -it --rm -v /dev:/dev -v /dev/shm:/dev/shm --privileged --net=host microros/micro-ros-agent:humble serial --dev /dev/myserial -b 2000000 -v4

Здесь --dev /dev/myserial — привязываемое устройство последовательного порта, значение можно также изменить на /dev/ttyUSB0 и т. п.

-b 2000000 — скорость передачи данных (baud rate).

Чтобы завершить работу прокси, нажмите Ctrl+C в терминале.

Обратите внимание: закрывать терминал напрямую нельзя, иначе Docker продолжит работать в фоновом режиме.

Если MCU несколько раз запускает переподключение к прокси, из-за чего ROS2 обнаруживает несколько одинаковых нод, это фактически не влияет на работу. Нажмите Ctrl+C, чтобы завершить работу прокси, а затем сбросьте MCU, чтобы переподключиться к прокси.

Ошибка запуска агента

Агент micro-ROS может быть запущен только в одном терминале. Если в одном терминале агент micro-ROS уже запущен в фоновом режиме, при повторном запуске агента появится ошибка. В этом случае нажмите Ctrl+C, чтобы завершить работу агента в исходном терминале агента, прежде чем запускать агент снова.

Если при следующем запуске агента возникает ошибка из-за того, что терминал был закрыт напрямую, можно перезапустить виртуальную машину/компьютер, чтобы решить проблему, либо завершить работу Docker вручную.

Как завершить работу Docker вручную:

Сначала узнайте текущий номер процесса Docker и завершите текущий процесс Docker с прокси.

docker ps -a | grep microros/micro-ros-agent
docker stop xxxxxxxxxx

2. Запуск агента micro-ROS из исходного кода

Установка зависимости tinyxml2

Введите в терминале следующую команду, чтобы установить tinyxml2:

cd ~/
git clone https://github.com/leethomason/tinyxml2.git
cd tinyxml2
mkdir build
cd build
sudo cmake ..
sudo make
sudo make install

Установка инструмента python3-rosdep

Введите в терминале следующую команду, чтобы установить инструмент rosdep. Если он уже установлен, этот шаг можно пропустить.

sudo apt install python3-rosdep

Компиляция окружения micro_ros_setup

Активируйте переменные окружения ROS2. В качестве примера рассмотрим версию humble. Если окружение уже активировано, этот шаг можно пропустить.

source /opt/ros/humble/setup.bash

Создайте рабочую область uros_ws в домашнем каталоге пользователя и перейдите в неё:

mkdir ~/uros_ws && cd ~/uros_ws
mkdir src

Скачайте файлы micro_ros_setup в папку src:

git clone -b $ROS_DISTRO https://github.com/micro-ROS/micro_ros_setup.git src/micro_ros_setup

Инициализируйте rosdep:

sudo rosdep init

Если возникает проблема с сетью, добавьте параметр -E:

sudo -E rosdep init

Если после всех перечисленных выше шагов rosdep всё равно не инициализируется и появляется ошибка, можно создать новый файл 20-default.list в каталоге /etc/ros/rosdep/sources.list.d/ и добавить в него следующее содержимое, а затем перейти к следующему шагу.

# os-specific listings first
yaml https://raw.githubusercontent.com/ros/rosdistro/master/rosdep/osx-homebrew.yaml osx

# generic
yaml https://raw.githubusercontent.com/ros/rosdistro/master/rosdep/base.yaml
yaml https://raw.githubusercontent.com/ros/rosdistro/master/rosdep/python.yaml
yaml https://raw.githubusercontent.com/ros/rosdistro/master/rosdep/ruby.yaml
gbpdistro https://raw.githubusercontent.com/ros/rosdistro/master/releases/fuerte.yaml fuerte

# newer distributions (Groovy, Hydro, ...) must not be listed anymore, they are
# being fetched from the rosdistro index.yaml instead

Обновите rosdep и установите соответствующие пакеты драйверов:

rosdep update && rosdep install --from-paths src --ignore-src -y

Скомпилируйте рабочую область:

colcon build

Активируйте окружение micro_ros_setup:

source install/local_setup.bash

Компиляция окружения micro_ros_agent

ros2 run micro_ros_setup create_agent_ws.sh
ros2 run micro_ros_setup build_agent.sh

Если при выполнении build_agent.sh возникает ошибка, выполните компиляцию повторно.

Запуск serial-прокси micro-ROS из исходного кода

Активируйте окружение агента micro_ros_agent:

source ~/uros_ws/install/local_setup.sh

Введите следующую команду, чтобы запустить serial-прокси из окружения ROS2:

ros2 run micro_ros_agent micro_ros_agent serial --dev /dev/myserial -b 2000000 -v4

Здесь --dev /dev/myserial — привязываемое устройство последовательного порта, значение можно также изменить на /dev/ttyUSB0 и т. п.

-b 2000000 — скорость передачи данных (baud rate).

Чтобы завершить работу прокси, нажмите Ctrl+C в терминале.

3. Запуск агента micro-ROS с использованием заводского образа

В заводской системе-образе функция прокси уже интегрирована и оформлена в виде скрипта. Достаточно выполнить следующую команду, чтобы включить прокси.

sh ~/start_agent.sh
