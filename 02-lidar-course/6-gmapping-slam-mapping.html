Построение карты Gmapping-SLAM

1. Содержание урока

Изучение алгоритма построения карты gmapping для функции SLAM-картографирования на роботе.

После запуска программы управляйте роботом с клавиатуры или геймпада для выполнения SLAM-картографирования и сохранения результата в виде растровой карты (raster map).

2. Введение в gmapping

2.1 Введение

  • gmapping работает только тогда, когда количество точек 2D-лидара в одном кадре меньше 1440. Если количество точек лидара в одном кадре больше 1440, возникнет ошибка [mapping-4] process has died.
  • Gmapping — широко распространённый SLAM-алгоритм с открытым исходным кодом, основанный на подходе фильтрующего SLAM (filtering SLAM).
  • Gmapping основан на алгоритме частичной фильтрации RBPF (Rao-Blackwellized Particle Filter), который разделяет задачи локализации в реальном времени и построения карты, выполняя сначала локализацию, а затем построение карты.
  • Gmapping вносит два основных улучшения в алгоритм RBPF: улучшение распределения предложений (proposal distribution) и селективную повторную выборку (selective resampling).

Преимущества: gmapping способен строить карты помещений в реальном времени, требует небольших вычислительных затрат для построения карт небольших пространств и обеспечивает высокую точность.

Недостатки: с ростом размера сцены увеличивается требуемое количество частиц, поскольку каждая частица хранит собственную карту, из-за чего растёт расход памяти и объём вычислений. Поэтому алгоритм не подходит для построения карт больших пространств. Кроме того, отсутствует обнаружение замыкания петли (loop detection), что может приводить к рассогласованию (несовпадению) карты — хотя увеличение количества частиц позволяет замкнуть карту, это происходит за счёт роста вычислительной нагрузки и расхода памяти.

3. Подготовка

3.1 Описание содержания

В этом уроке в качестве примера используется Jetson Orin NX. Для плат Raspberry Pi и Jetson Nano необходимо открыть терминал и ввести команду для входа в Docker-контейнер. После входа в контейнер вводите команды этого урока уже внутри него. Инструкции по входу в Docker-контейнер см. в руководстве к изделию [Configuration and Operation Guide] — [Entering the Docker] (для пользователей Jetson Nano и Raspberry Pi 5, см. соответствующий раздел). Для плат Orin и NX достаточно просто открыть терминал и ввести команды этого урока.

3.2 Запуск агента

Примечание: перед тестированием всех примеров необходимо сначала запустить агента в Docker. Если он уже запущен, повторно запускать его не нужно.

Введите команду в терминале робота:

sh start_agent.sh

4. Запуск примера

4.1 Процесс построения карты

Обратите внимание:

  • При построении карты, чем медленнее скорость (в первую очередь скорость поворота), тем лучше результат. Если двигаться слишком быстро, результат будет очень плохим.
  • Для контроллеров серии Jetson Nano и Raspberry Pi необходимо сначала войти в Docker-контейнер (порядок действий см. в разделе [Docker course chapter — Entering the robot's Docker container]).

В терминале робота запустите команду построения карты:

ros2 launch slam_mapping gmapping.launch.py

Функцию визуализации rviz можно запустить как на стороне робота, так и на стороне виртуальной машины. Выберите любой из двух способов запуска. Запрещается запускать её одновременно и на виртуальной машине, и на роботе.

В качестве примера рассмотрим настройку на виртуальной машине: откройте терминал и запустите интерфейс визуализации rviz:

ros2 launch slam_view slam_view.launch.py

Команда запуска интерфейса визуализации rviz на роботе:

ros2 launch slam_mapping slam_view.launch.py

Откройте на виртуальной машине ещё один терминал и запустите узел управления с клавиатуры (также можно использовать управление с геймпада, для этого нужно предварительно запустить узел управления с геймпада, см. [5. Chassis Control — 2. Controller Control]):

ros2 run yahboomcar_ctrl yahboom_keyboard

Кликните по окну терминала и нажмите z, чтобы соответствующим образом снизить скорость.

Нажимайте I, <, J и L для управления движением робота вперёд, назад, поворотом влево и поворотом вправо соответственно и перемещайте робота для завершения построения карты.

4.2 Сохранение карты

Откройте на роботе новый терминал и сохраните карту:

ros2 launch slam_mapping save_map.launch.py

Если терминал выводит сообщение «Map saved successfully», это означает, что карта успешно сохранена. Если сохранение карты не удалось, попробуйте сохранить ещё раз.

Путь сохранения карты следующий:

Jetson Orin Nano, Jetson Orin NX:

/home/jetson/M3Pro_ws/install/M3Pro_navigation/share/M3Pro_navigation/map

Jetson Orin Nano, Raspberry Pi:

Сначала необходимо войти в Docker:

/root/M3Pro_ws/install/M3Pro_navigation/share/M3Pro_navigation/map/

Изображение в формате PGM и файл yahboom_map.yaml:

image: yahboom_map.pgm
mode: trinary
resolution: 0.05
origin: [-10, -10, 0]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.25

Разбор параметров:

  • image: путь к файлу карты — может быть абсолютным или относительным.
  • mode: этот атрибут может принимать одно из значений trinary, scale или raw, в зависимости от выбранного режима. Режим trinary используется по умолчанию.
  • resolution: разрешение карты, метры/пиксель.
  • origin: 2D-положение (x, y, yaw) нижнего левого угла карты, где yaw — поворот против часовой стрелки (yaw=0 означает отсутствие поворота). В настоящее время многие части системы значение yaw игнорируют.
  • negate: инвертировать ли смысл белого/чёрного, свободного/занятого (на интерпретацию порогов не влияет).
  • occupied_thresh: пиксели с вероятностью занятости выше этого порога считаются полностью занятыми.
  • free_thresh: пиксели с вероятностью занятости ниже этого порога считаются полностью свободными.

5.4 Файлы конфигурации

Путь к файлу конфигурации:

Jetson Orin Nano, Jetson Orin NX:

/home/jetson/M3Pro_ws/src/M3Pro_core/slam_gmapping/params/slam_gmapping.yaml

Jetson Orin Nano, Raspberry Pi:

Сначала необходимо войти в Docker:

root/M3Pro_ws/src/M3Pro_core/slam_gmapping/params/slam_gmapping.yaml

Параметры конфигурации по умолчанию:

slam_gmapping:
  ros__parameters:
     # Порог обновления по углу (радианы): карта обновляется, когда робот поворачивается больше этого угла
     angularUpdate: 0.25
     # Шаг выборки по углу (радианы): шаг поиска по углу при сопоставлении сканов
     astep: 0.05
     # Имя базовой системы координат робота
     base_frame: base_footprint
     # Имя системы координат карты
     map_frame: map
     # Имя системы координат одометрии
     odom_frame: odom
     # Условие остановки итераций сопоставления сканов: остановка, когда изменение параметра меньше этого значения
     delta: 0.05
     # Максимальное число итераций сопоставления сканов
     iterations: 5
     # Размер ядра, используемого при сопоставлении сканов, влияет на плавность сопоставления
     kernelSize: 1

     # Диапазон выборки при грубом сопоставлении сканов (метры)
     lasamplerange: 0.005
     # Шаг выборки при грубом сопоставлении сканов (метры)
     lasamplestep: 0.005
     # Порог обновления по перемещению (метры): карта обновляется, когда робот перемещается больше этого расстояния
     linearUpdate: 0.5
     # Диапазон выборки при точном сопоставлении сканов (метры)
     llsamplerange: 0.01
     # Шаг выборки при точном сопоставлении сканов (метры)
     llsamplestep: 0.01
     # Ковариация шума измерения лидара
     lsigma: 0.075
     # Число пропускаемых лучей лидара: 0 означает использование всех точек лидара
     lskip: 0
     # Шаг линейной выборки (метры): шаг поиска по перемещению при сопоставлении сканов
     lstep: 0.05
     # Интервал обновления карты (секунды)
     map_update_interval: 3.0
     # Максимальная дальность лидара (метры): точки за пределами этого расстояния игнорируются
     maxRange: 6.0
     # Максимальная используемая дальность лидара (метры): максимальное расстояние, используемое при построении карты
     maxUrange: 4.0
     # Минимальный порог оценки сопоставления сканов: совпадения ниже этого значения отбрасываются
     minimum_score: 0.0
     # Порог вероятности занятости: ячейки выше этого значения считаются занятыми
     occ_thresh: 0.25
     # Коэффициент усиления: влияет на скорость обновления карты
     ogain: 3.0
     # Число частиц в фильтре частиц
     particles: 30
     # Параметры QoS (Quality of Service)
     qos_overrides:
       /parameter_events:
         publisher:
              depth: 1000            # Глубина очереди сообщений
              durability: volatile # Политика сохранности
              history: keep_all       # Политика истории
              reliability: reliable # Политика надёжности
       /tf:
         publisher:
              depth: 1000
              durability: volatile
              history: keep_last      # Хранить только последнее сообщение
              reliability: reliable
     # Порог повторной выборки: повторная выборка запускается, когда эффективное число частиц падает ниже этой доли
     resampleThreshold: 0.5
     # Ковариация углового шума при сопоставлении сканов
     sigma: 0.05
     # Параметр модели одометрии: доля линейной ошибки, вызванной линейным движением
     srr: 0.1
     # Параметр модели одометрии: доля угловой ошибки, вызванной линейным движением
     srt: 0.2
     # Параметр модели одометрии: доля линейной ошибки, вызванной угловым движением
     str: 0.1
     # Параметр модели одометрии: доля угловой ошибки, вызванной угловым движением
     stt: 0.2
     # Интервал обновления по времени (секунды): обновлять карту даже когда робот неподвижен
     temporalUpdate: 1.0
     # Период публикации преобразований (секунды)
     transform_publish_period: 0.05
     # Использовать время симуляции
     use_sim_time: false
     # Максимальная граница карты по оси X (метры)
     xmax: 100.0
     # Минимальная граница карты по оси X (метры)
     xmin: -100.0
     # Максимальная граница карты по оси Y (метры)
     ymax: 100.0
     # Минимальная граница карты по оси Y (метры)
     ymin: -100.0
