22. Платформа симуляции Gazebo в ROS2

1. Введение в Gazebo

Gazebo — самая распространённая платформа 3D-физической симуляции в системе ROS. Она поддерживает динамический движок и обеспечивает высококачественный рендеринг графики. Она не только симулирует робота и его окружающую среду, но и учитывает физические свойства, такие как трение и упругость.

Например, если мы хотим разработать марсианский ровер, мы можем симулировать поверхность Марса в Gazebo. Или, если мы разрабатываем дрон, ограниченный заряд батареи и лётные ограничения не позволяют часто проводить эксперименты с реальным дроном. В таких случаях можно сначала провести симуляцию в Gazebo, а затем развернуть решение на реальном дроне после полной разработки алгоритма.

Такие платформы симуляции, как Gazebo, помогают нам проверять робототехнические алгоритмы, оптимизировать конструкцию робота и тестировать приложения для роботов, открывая больше возможностей для разработки робототехники.

Примечание: этот раздел предназначен только для ознакомления. В учебном курсе не производится настройка окружения, поскольку мы используем отладку на реальном устройстве.

2. Установка и запуск

  • Установите Gazebo с помощью команды apt
sudo apt install ros-${ROS_DISTRO}-gazebo-*
  • Запустите Gazebo
  • Запустите Gazebo с помощью следующей команды или напрямую через значок на рабочем столе
gazebo --verbose -s libgazebo_ros_init.so -s libgazebo_ros_factory.so

После запуска вы должны увидеть следующую страницу:

  • Опционально: чтобы обеспечить корректную загрузку моделей, можно скачать offline-модели и разместить их в директории ~/.gazebo/models. Ссылка для скачивания: https://github.com/osrf/gazebo_models

3. Запуск ноды и сервиса Gazebo

  1. Просмотр ноды
ros2 node list

Корректный ответ: /gazebo

  1. Просмотр внешних сервисов, предоставляемых нодой:
ros2 service list

Вы увидите следующий результат:

Не считая последних нескольких обычных сервисов, мы сосредоточимся только на первых трёх особых сервисах:

  • /spawn_entity, используется для загрузки моделей в Gazebo
  • /get_model_list, используется для получения списка моделей
  • /delete_entity, используется для удаления загруженных моделей в Gazebo

4. Создание пакета функций

  • Создайте пакет myrobot для хранения нашей модели URDF и файлов запуска.
ros2 pkg create myrobot --build-type ament_cmake
  • Перейдите в директорию myrobot и создайте папки launch и urdf. В папке urdf создайте файл demo01_base.urdf. Это простой демонстрационный файл, содержащий только базовый куб.
<robot name="myrobot">
     <link name="base_link">
           <visual>
               <geometry>
                    <box size="0.2 0.2 0.2"/>
               </geometry>
               <origin xyz="0.0 0.0 0.0"/>
           </visual>
           <collision>
               <geometry>
                    <box size="0.2 0.2 0.2"/>
               </geometry>
               <origin xyz="0.0 0.0 0.0"/>
           </collision>
           <inertial>
               <mass value="0.1"/>
               <inertia ixx="0.000190416666667" ixy="0" ixz="0" iyy="0.0001904"
iyz="0" izz="0.00036"/>
           </inertial>
     </link>
     <gazebo reference="base_link">
           <material>Gazebo/Red</material>
     </gazebo>
</robot>

5. Написание файла запуска

Написание файла запуска состоит из двух основных частей: запуск файла Gazebo, а затем загрузка модели робота в Gazebo.

start_gazebo_cmd =          ExecuteProcess(
          cmd=['gazebo', '--verbose','-s', 'libgazebo_ros_init.so', '-s',
'libgazebo_ros_factory.so'],
          output='screen')

Эта команда запускает Gazebo. Это простая команда запуска, не особо сложная. Ниже приведена команда для загрузки модели:

 spawn_entity_cmd = Node(
          package='gazebo_ros',
          executable='spawn_entity.py',
          arguments=['-entity', robot_name_in_model,         '-file', urdf_model_path ],
output='screen')

Обратите внимание на следующие два параметра в этой команде: -entity — это имя файла модели, а -file — это параметр, загружаемый через файл urdf. Позже мы также увидим, как модель загружается через топик. Создайте файл bringup_model.launch.py в директории launch. Полный файл запуска выглядит так:

import os
from launch import LaunchDescription
from launch.actions import ExecuteProcess
from launch_ros.actions import Node
from launch_ros.substitutions import FindPackageShare
from launch_ros.parameter_descriptions import ParameterValue
from launch.substitutions import Command


def generate_launch_description():
     robot_name_in_model = 'myrobot'
     package_name = 'myrobot'
     urdf_name = "demo01_base.urdf"


     ld = LaunchDescription()
     pkg_share = FindPackageShare(package=package_name).find(package_name)
     urdf_model_path = os.path.join(pkg_share, f'urdf/{urdf_name}')


     # Start Gazebo server
     start_gazebo_cmd =        ExecuteProcess(
          cmd=['gazebo', '--verbose','-s', 'libgazebo_ros_init.so', '-s',
'libgazebo_ros_factory.so'],
          output='screen')


     # Launch the robot
     spawn_entity_cmd = Node(
          package='gazebo_ros',
          executable='spawn_entity.py',
          arguments=['-entity', robot_name_in_model,         '-file', urdf_model_path ],
output='screen')


     ld.add_action(start_gazebo_cmd)
     ld.add_action(spawn_entity_cmd)


     return ld
  • Заполните следующее содержимое в CMakeLists, чтобы установить наши папки urdf и launch в директорию install
install(
     DIRECTORY urdf launch
     DESTINATION share/${PROJECT_NAME}
)
  • Затем скомпилируйте и запустите пакет функций
colcon build --packages-select myrobot
  • Обновите переменные окружения и запустите файл запуска
ros2 launch myrobot bringup_model.launch.py
