Привязка идентификатора устройства

12. Привязка идентификатора устройства

  1. Команда просмотра устройств
  2. Установление соответствия портов 2.1. Привязка устройства 2.2. Введение в синтаксис файла правил
  3. Проверка соответствия
  4. Привязка порта USB

Когда робот использует два или более USB-устройств последовательного порта, соответствие между именем устройства и самим устройством не является фиксированным, а назначается последовательно в порядке подключения устройств к системе.

Подключение сначала одного устройства, а затем другого позволяет определить соответствие между устройством и его именем, однако постоянно подключать и отключать устройство при каждом запуске системы очень неудобно. Последовательный порт можно привязать к фиксированному имени устройства. Независимо от порядка подключения, устройство будет привязано к новому имени устройства. Нам останется лишь использовать это новое имя устройства для чтения и записи данных с устройства.

1. Команда просмотра устройств

Просмотр параметров устройства камеры

Введите в терминале следующую команду, чтобы посмотреть соответствие между размером пикселя камеры и частотой кадров.

v4l2-ctl --list-formats-ext

Просмотр идентификатора устройства

lsusb

Как видно на рисунке ниже, для камеры глубины Astra в официальной документации описана привязка устройства к номеру ID каждого устройства. Как правило, контроллер привязывать не требуется, привязка в основном нужна для PCB (платы управления) и радара (лидара).

Просмотр идентификатора устройства

ll /dev/

2. Установление соответствия портов

2.1. Привязка устройства

Привязка Astra

В папке scripts пакета функций astra_camera есть файл create_udev_rules.

Запустите этот файл, чтобы выполнить привязку автоматически.

Выполните следующую команду

./create_udev_rules

Перейдите в каталог rules.d

cd /etc/udev/rules.d/

Там можно найти файл 56-orbbec-usb.rules — это файл привязки устройства камеры Astra.

Привязка PCB и лидара

Перейдите в каталог rules.d

cd /etc/udev/rules.d/

Создайте новый файл rplidar.rules

sudo touch rplidar.rules
sudo chmod 777 rplidar.rules

Откройте файл rplidar.rules

sudo vim rplidar.rules

Впишите следующее содержимое

KERNEL=="ttyUSB*", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523",
MODE:="0777", SYMLINK+="myserial"
KERNEL=="ttyUSB*", ATTRS{idVendor}=="10c4", ATTRS{idProduct}=="ea60",
MODE:="0777", SYMLINK+="rplidar"

Выйдите, чтобы правила вступили в силу

sudo udevadm trigger
sudo service udev reload
sudo service udev restart

2.2. Введение в синтаксис файла правил

KERNEL=="ttyUSB*", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523",
MODE:="0777", SYMLINK+="myserial"
KERNEL=="ttyUSB*", ATTRS{idVendor}=="10c4", ATTRS{idProduct}=="ea60",
MODE:="0777", SYMLINK+="rplidar"

Разбор

KERNEL                       #Имя устройства, соответствующее событию
ATTR{filename}               # Соответствие атрибутам sysfs устройства события.
idVendor                     # Номер производителя
idProduct                    # Номер продукта
SYMLINK                      # Создать символическую ссылку для файла устройства в /dev/.
Просто задаёт этому устройству псевдоним.
MODE                         # Задать права доступа для устройства.

Из [6.1] видно, что номер устройства PCB — [ttyUSB0], и он легко может измениться. Номер ID — [1a86, 7523] — фиксированный. [ttyUSB*] означает, что независимо от того, каким станет номер устройства в будущем — [ttyUSB], за которым следует [0, 1, 2, 3, 4, ...] — все они будут привязаны к [myserial]; то же самое верно для устройства радара [ttyUSB1]; аналогично и для других устройств, которые нужно привязать.

3. Проверка соответствия

Просмотр номера устройства

ll /dev/

PCB

лидар

4. Привязка порта USB

Все описанные выше случаи касаются устройств с разными номерами ID. Если номера ID радара и PCB совпадают, либо если подключено два или более PCB (радаров) с одинаковым ID, описанная выше привязка приведёт к путанице.

В этом случае необходимо привязать USB-порт. После привязки USB-порт нельзя будет произвольно изменить — каждое устройство сможет подключаться только к строго определённому USB-порту.

Способ привязки: возьмём в качестве примера [ttyUSB0] и проверим, к какому порту в данный момент подключено устройство.

udevadm info --attribute-walk --name=/dev/ttyUSB0 |grep KERNELS

Нам нужно внести изменения в файл правил

# KERNEL=="ttyUSB*", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523",
MODE:="0777", SYMLINK+="myserial"          # до изменения
KERNELS=="1-2.1.3", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523",
MODE:="0777", SYMLINK+="myserial"           # после изменения
